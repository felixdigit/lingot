A surface that merely renders has not shipped -- it ships when it is crafted. Design is a gate, not a finishing touch.

1. **Load the venture's design system first.** Every surface speaks ONE visual language -- the venture's own, never a generic default. Read the design canon (its craft rules, tokens, type, palette) before touching a pixel. Each venture states its own language; introduce no second one.

2. **Real craft, not the minimum.** The bar is a considered, ambitious surface -- hierarchy, rhythm, restraint -- not "it renders." Coordinate-nudging and box-stacking are not design. A change that makes the task easier by degrading the surface is rejected.

3. **Runtime speed is craft.** A beautiful surface that loads slowly is not done; performance is in scope.

4. **Judge the rendered thing.** Evaluate the surface as it actually renders -- the real route, the real artefact, in light and dark where both apply -- not the code that should produce it. When pointing Felix at a route, send the complete clickable URL, never a bare path.

5. **External artefacts carry craft too.** A report, a deck, a client page is a designed object: typographic care, sourced figures, a coherent system. The same gate applies to them.

**Done** = the surface speaks the venture's one language, holds real craft over the minimum, performs, and has been judged as rendered -- not asserted from the code.
